# Synthetic test/train data — generation plan

Goal: use Claude to produce a diverse set of **synthetic dictation inputs** (raw MedASR-style
speech-to-text transcripts) to test and eventually help fine-tune the local MedGemma pipeline —
without ever exposing real patient data.

This file contains the plan **and** 15 ready-to-use sample inputs (see "Sample inputs" below).

---

## Hard guardrails (read first)

1. **Never paste real patient transcripts into Claude / any cloud tool.** Claude runs on
   Anthropic's cloud, which is **not** a BAA'd service for this practice (only Google Workspace is —
   see `CLAUDE.md` and [[google_workspace_baa_exception]]). Real transcripts are PHI; sending them to
   Claude is a HIPAA disclosure to a non-BAA third party. This is the exact reason the prototype's
   cloud call was removed. **Synthetic data only.**
2. **Claude generates INPUTS, not training labels.** The gold *output* note that MedGemma should
   learn from must be a **clinician-reviewed, corrected** note — not an LLM-authored one. Training on
   unreviewed model output bakes the model's hallucinations in. Per `CLAUDE.md`, the fine-tune corpus
   is "the clinician's own reviewed notes."
3. **Automated scoring ≠ clinical validation.** `scripts/validate_quality.py` catches the
   *mechanical* defect classes (structure, field presence, fact capture, no fabricated codes). Only
   the clinician can judge clinical acceptability.

---

## The pipeline

```
[1] GENERATE            [2] RUN                    [3] SCORE                  [4] IMPROVE
Claude writes    ->   feed each transcript   ->   auto-score mechanical  ->  fix the template spec
synthetic, varied     through the REAL             classes (validate_        (prompt eng) OR add a
transcripts           pipeline on the target       quality.py style) +       deterministic backstop;
(inputs only)         machine (Ollama/MedGemma)    clinician eyeballs        re-run to confirm
                                                    clinical quality
```

- **[1] Generate.** Use Claude with the recipe below to produce transcripts that vary along the
  dimensions that break a 4B CPU model (see "Coverage matrix"). Each transcript is tagged with the
  template it targets and the failure modes it seeds.
- **[2] Run.** On the provisioned machine, pipe each transcript through the production path
  (`build_prompt` → `generate_note` → `postprocess` → `traceability` → `cpt`). The unit tests stub
  the model, so this is the only thing that proves real behavior. `scripts/verify_pipeline.py` /
  `scripts/validate_quality.py` already do this for one input — generalize them to loop over the set.
- **[3] Score.** Two layers:
  - *Mechanical (automated):* reuse the `validate_quality.py` scorecard — 4 blocks present, every
    template field present, stated facts captured, no surviving model-authored CPT/ICD, no unflagged
    fabricated pain scores, duplication/length/speed.
  - *Clinical (human):* the clinician reads the note and rates acceptability + fixes it. That
    corrected note is the future fine-tune label (guardrail #2).
- **[4] Improve.** When a whole *class* of mistake shows up, fix it upstream, not per-note (the
  standing workflow instruction in `CLAUDE.md`): prefer a template-spec/prompt change; if the failure
  is a detectable, meaning-safe pattern, move it into `postprocess.py`/`traceability.py` as a
  backstop. Re-run the set to confirm the fix held and nothing regressed.

**Fine-tuning comes last.** Only after (a) prompt/spec refinement + backstops are exhausted, and
(b) you have a stack of clinician-corrected notes, build a QLoRA set of
`(synthetic dictation → clinician-corrected note)` pairs. Don't fine-tune on Claude's or MedGemma's
own unreviewed output.

---

## How to prompt Claude to generate MORE inputs (reusable recipe)

> "Generate N synthetic outpatient physical-therapy dictations for the `<template id>` template.
> These are raw MedASR speech-to-text transcripts of a therapist (fluent but non-native English)
> dictating after a session. **Fake data only — no real patients.** Vary: patient condition/context,
> length, and messiness. Include the disfluencies MedASR produces: fillers (um, uh, like), false
> starts, mid-sentence self-corrections, checklist answers ('…, yes'), occasional garbled/[inaudible]
> passages, and once in a while a value stated two different ways (a conflict). For some, deliberately
> OMIT a required field, or state a section with NO number, so the gap-flagging and 'never invent a
> value' rules get exercised. Do NOT include patient names. Tag each with the template and the
> failure modes it seeds."

### Dimensions to vary (so the set has real coverage)

| Dimension | Values to spread across |
|---|---|
| Template | `initial`, `initial_updated` (block/SOAP), `followup` (carry-forward) |
| Body region / condition | knee, hip, shoulder, back, neck, ankle, neuro (CVA/Parkinson's), cardiopulmonary debility |
| Cleanliness | clean & complete · moderate disfluency · heavy garble |
| Completeness | all fields present · a required field missing · a value stated with no number |
| Traps | self-correction · checklist "…, yes" · two-value conflict · long med list (11+) · no pain/vitals stated (must NOT invent) · no code stated (must NOT author CPT/ICD) |
| Carry-forward (followup only) | value that must be *reconciled* today · a goal that is MET · all STG met (Plan must justify continued care via unmet LTG) |
